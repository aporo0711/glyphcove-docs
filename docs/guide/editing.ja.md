# プレビュー編集（WYSIWYG）

**English**: [editing.md](editing.md)

- 開き方: `.md` を右クリック → **「プレビュー編集で開く」**（エクスプローラー / エディタタブ / コマンドパレットは「GlyphCove: プレビュー編集で開く」）
- 編集可能: 段落・見出し・**太字**・*斜体*・`コード`・~~取り消し線~~・リンク・箇条書き/番号/タスクリスト（ネスト対応）・引用・コードブロック・水平線・**表**（挿入、行/列の追加・削除、列揃え、Tabでセル移動）
- ショートカット: **Ctrl+B**（太字）／**Ctrl+I**（斜体）／**Ctrl+E**（インラインコード）／**Ctrl+Shift+X**（取り消し線）／**Ctrl+A**（すべて選択）。このうち **Ctrl+B・Ctrl+E・Ctrl+Shift+X・Ctrl+A は VS Code 本体のショートカット**（サイドバーの開閉／ファイルを開く／拡張機能ビュー／すべて選択）と重なるため、**GlyphCove のエディタが選択されている間だけエディタ側が受け取り**、VS Code 側の動作は起こしません（ほかのエディタやパネルにフォーカスがあるときは今までどおりです）。この割り当てが不都合な場合は、VS Code の「キーボードショートカット」で `glyphcove.keepShortcutInEditor` を検索して外してください
- ツールバー: **リンクの入力欄は「🔗」を押したときだけ**、**表の操作ボタンは表にカーソルがあるときだけ**出ます（本文の領域を狭めないため）
- 検索・置換: **Ctrl+F で検索、Ctrl+H で置換**（ツールバーの「🔍」からも開けます）。大文字小文字の区別・単語単位・正規表現を切り替えられ、F3 / Shift+F3（または Enter / Shift+Enter）で前後の一致へ移動、Esc で閉じます。**保護中のブロックの中もヒットは表示しますが置換はしません**（何件スキップしたかを表示します）。すべて置換は 1 回の Undo で元に戻せます。正規表現モードでは置換文字列に `$1` / `$&` が使えます
- 目次（アウトライン）: **既定では非表示**です。ツールバー左端の **「≡」** を押すと左側に見出しの一覧が出て、**クリックでその見出しへ移動**、スクロールに追従して現在位置がハイライトされます。もう一度押すと閉じます。開いた状態で始めたい場合は設定 `glyphcove.outline.show` を on にしてください（VS Code 標準の「アウトライン」ビューはテキストエディタ専用で、このエディタでは空になります）
- リンクを開く: **Ctrl+クリック**（Mac は Cmd+クリック）で、`#見出し` は文書内を移動、`./other.md` は GlyphCove で開き、`http(s)` / `mailto:` は既定のブラウザ・メールクライアントで開きます。通常のクリックはカーソル移動のままです（リンクのテキストを編集できるようにするため）。**Ctrl を押している間はリンクの上でマウスカーソルがポインター（指の形）になります** — VS Code 本体のエディタと同じ合図です（押していない間は文字カーソルのまま。素のクリックは「開く」ではないため）
- リンクの検査: プレビューで開いている文書の**壊れたリンクを「問題」パネルに表示**します — 存在しない相対リンク先・画像ファイル、文書内に無い `#見出し` アンカー、リンク先の `.md` に無い `#見出し`（警告）、および**素の絶対パス**（`D:/img/x.png` のような書き方。HTML 出力では画像が表示されなくなるため。情報）。**開いている文書だけ**が対象で、ワークスペース全体は走査しません。編集すると約 0.5 秒後に更新され、閉じると消えます。不要なら設定 `glyphcove.diagnostics.links` を off にしてください
- リンクの設定: **文字を選択してツールバーの「🔗」** を押すと URL の入力欄が開きます（何にリンクを張るかが入力欄に表示されます）。Enter で確定、Esc で取り消し。選択せずに押した場合は、入力した URL がそのままリンクの文字列として挿入されます。リンクの上で「🔗」を押すとリンクを解除します
- front matter の編集: 文書先頭の `---` で囲まれた YAML は保護中のカードで表示されますが、**カードの「編集」ボタンで生の YAML をそのまま編集できます**（Ctrl+Enter で保存、Esc で取り消し）。キー/値のフォームではなく生の YAML なので、**コメントもキーの順序もそのまま残ります**。保存は 1 回の Undo で元に戻せます
- 画像: 相対パス・`data:` URI の画像をプレビューに実表示。ツールバーの「画像を挿入」でファイルを選択（ワークスペース外のファイルは文書の隣へコピーを推奨）。**外部 `http(s)` 画像は読み込みません**（プレースホルダ表示。文書を開いただけで外部通信が発生しない設計）
- 表の貼り付け: **Excel / Word からコピーした表を、表のまま貼り付けられます**。セル内の複数行はセル内改行（`<br>`）として保持されます。Word の表の**セル結合は貼り付け時に解除**され、値は結合範囲の左上のセルに入ります（Markdown の表にセル結合の表現が存在しないため。解除したときは通知が出ます。表の中に入れ子になった表はテキストに展開）。**Web ページの表も同じように貼り付けられます** — 結合セルは Word と同じ規則で展開するので、`colspan` / `rowspan` のある表でも値が 1 列ずれません
- 罫線表の貼り付け: **罫線で囲まれた表のテキストを貼り付けると表になります** — `┌─┬─┐` の**単線の罫線素片**、`+---+` の ASCII 罫線（`mysql` / `psql` などの端末出力）、**プレーンテキストとしてコピーした Markdown の表**が対象です。**セルは縦線で区切って読み取ります**（桁位置は数えません — 日本語が 1 文字でも混ざると桁は揃わないため）。**二重線・太線・角丸の罫線、セル結合、崩れた格子は表にせず、これまでどおり文字として貼り付けます**（推測で修復すると、元のテキストが黙って書き換わるため）
- CSV / TSV の貼り付け: **カンマ区切り・タブ区切りのテキストを貼り付けると表になります**（`.csv` をエディタで開いてコピー、ログの貼り付けなど）。引用符付きの値（`"a,b"`）やセル内改行にも対応します。**判定は厳しめ**で、2 行以上・全行の列数が一致・2 列以上のときだけ表にします（カンマの場合はさらに「3 行以上または 3 列以上」を要求します — 「はい, いいえ」のような 2 行 2 列は文章と区別できないため）。条件を満たさないときは**これまでどおりの文字として貼り付きます**。**Excel からのコピーはこの経路を通りません**（Excel は表そのものもクリップボードに載せるので、そちらを使います）
- 画像の貼り付け・ドラッグ&ドロップ: スクリーンショットや画像ファイルを Ctrl+V / ドロップで挿入できます。**ファイルは常に `<文書名>_images/` へ保存**し、Markdown にはパスだけを書きます（base64 は生成しません）。ワークスペース内にある画像をドロップした場合はコピーせずその場所を参照します。**VS Code のエクスプローラー（ツリー）からドラッグするときは Shift を押しながらドロップ**してください（VS Code の仕様で、Shift なしのドロップは「ファイルを開く」操作になります）
- 図（draw.io）の編集: draw.io で「**編集可能な図として保存**」した `*.drawio.svg` / `*.drawio.png` を貼り付けると、プレビュー上の画像を**ダブルクリックするだけで draw.io エディタが横に開きます**（[Draw.io Integration](https://marketplace.visualstudio.com/items?itemName=hediet.vscode-drawio) 拡張が必要。未インストールなら案内が出ます）。保存すると**プレビューの図が自動で更新**されます。それ以外の画像をダブルクリックすると、VS Code の既定のエディタ（画像プレビュー、`.svg` はテキスト）で開きます
- 図形（ステンシル）の貼り付け: **draw.io 上で図形を選択してコピーし、プレビューに Ctrl+V** すると、図を持った `ステンシル.drawio.svg` が `<文書名>_images/` に作られて画像として挿入されます（これまでは `%3CmxGraphModel…` という文字列が入っていました）。Draw.io Integration 拡張と Edge/Chrome がインストールされていれば、**貼り付けるだけで自動的に実際の図が描画されます**（同拡張が同梱する draw.io 本体をヘッドレスブラウザでバックグラウンド実行。初回は起動のため数秒かかることがあります）。拡張・ブラウザがない場合や描画に失敗した場合は案内のプレースホルダ表示のままになり、**ダブルクリックして draw.io で開き保存すると描画**されます（以降は上記「図（draw.io）の編集」と同じ流れ）
- 画像のリサイズ: 画像を選択して四隅のハンドルをドラッグすると幅を変更（縦横比は維持）。サイズ付き画像は GitHub 互換の `<img src width>` 形式で保存されます（Markdown 標準にサイズ記法がないため。DOCX 変換ではインライン HTML 扱いになりテキスト化＋警告）。⚠ **ハンドルはドラッグ操作にしか反応せず、キーボードだけでは幅を変えられません**（WCAG 2.2 の 2.1.1 / 2.5.7 / 2.5.8。→ [既知の正規化・制限](limitations.ja.md)）— 幅を数値で指定したいときは、**ツールバーの「ソースを開く」**でソースを横に並べて開き、`<img src="..." alt="..." width="480">` の `width` の数値を直接書き換えてください（この形式はプレビューでもそのまま画像として表示されます）
- 埋め込み（base64 / `data:` URI）画像をリサイズすると、`<文書名>_images/` フォルダへ自動で書き出してファイル参照に置き換えます（**方針: 画像は外部ファイルで持ち、base64 は生成しない**）。書き出し後の Markdown にはパスとサイズだけが残ります
- 見出しの項番の自動採番: 見出しの先頭にある項番（`1.` / `1.1`）を書き換えると、**後続の見出しの項番が自動で追従**します（`2.` を `5.` に直すと以降が 6, 7 … になり、中項目も `5.1` `5.2` と振り直されます）。見出しを削除したときも後続が詰まります。編集中の見出しとそれより前の見出しは書き換えません。対象は**すでに項番が付いている見出しだけ**で、「はじめに」のような項番のない見出しや「第2章 …」の書き方には手を触れません。ツールバーの **「№」ボタン**で文書全体を振り直すこともできます（先頭の項番は起点として尊重）。自動追従が不要なら設定 `glyphcove.numbering.auto` を off にしてください
- Mermaid 図の描画: ` ```mermaid ` のコードブロックが**プレビュー上で図として表示**されます（mermaid を拡張に同梱・完全オフライン。初回表示時のみ読み込みのため一瞬かかります）。**図をクリックするか、カーソルがブロックに入るとソースが開き**、編集すると図がライブ更新されます（カーソルが出ると図のみに戻る）。構文エラー時はエラーメッセージを表示し、**ソースはそのまま保持**されます（直前の正常な図は薄表示で残ります）
- 図の描画は**画面に近づいてから**行います: Mermaid / PlantUML の図は、**その位置までスクロールしそうになった時点で描画**します（画面の 300px 手前から先読み）。図の多い文書でも、開いた瞬間に全部の図を描くことがなくなり、最初の画面が早く出ます。**未描画の図の場所には高さが確保されている**ので、描画が届いても本文が飛び跳ねません。画面外で編集した図は、**見えたときに最新のソースで 1 回だけ**描き直します（数式は KaTeX で軽いため、これまでどおりすぐ描画します）
- PlantUML 図の描画: ` ```plantuml ` / ` ```puml ` のコードブロックも同じ操作感で図として表示・ライブ更新されます（`@startuml` を書かなくてもフェンス言語だけで OK。`@startmindmap` などの明示ブロックもそのまま使えます）。描画には **Java と plantuml.jar が必要**です — [PlantUML 拡張機能（jebbs.plantuml）](https://marketplace.visualstudio.com/items?itemName=jebbs.plantuml)がインストールされていれば**同梱の jar を自動で再利用**します（設定 `glyphcove.plantuml.jarPath` / `javaPath` で明示指定も可能）。無い場合は案内メッセージが表示されるだけで、ソースはそのまま編集できます。レイアウトは Graphviz 不要の smetana を使用（クラス図なども dot なしで描画）。構文エラーは**エラー画像ではなく行番号付きメッセージ**で表示します
- GitHub Alerts: `> [!NOTE]` / `> [!TIP]` / `> [!IMPORTANT]` / `> [!WARNING]` / `> [!CAUTION]` で始まる引用が、**種類ごとの色付きの囲み**として表示されます。プレビューでは `[!NOTE]` の文字はそのまま編集できる状態で残り（Markdown は 1 バイトも変わりません）、HTML / PDF / Word へ変換すると、種類ごとの背景色と左罫線が付いた囲みになります。見出しは**その文書の言語**で入ります（日本語なら「ノート」「ヒント」「重要」「警告」「注意」、英語なら `Note` / `Tip` / `Important` / `Warning` / `Caution`）。囲みの中を編集しても `> [!NOTE]` の行はそのままの形で保たれるので、GitHub 等で開いたときの表示も崩れません
- 数式の描画: `$$` で囲んだ行が**プレビュー上で数式として表示**されます（KaTeX を拡張に同梱・完全オフライン）。図と同じ操作感で、**数式をクリックするか、カーソルがブロックに入るとソース（TeX）が開き**、編集すると数式がライブ更新されます。段落の途中に書くインライン数式は `$$a^2 + b^2 = c^2$$` のように**同じ `$$` で囲み**、クリックすると小さな入力欄が開いて TeX を直せます（Enter で確定 / Esc で取消 / 空にすると数式を削除）。新しく書くときは、**ツールバーの「∑」**でブロック数式にするか、行頭で `$$` と打つとブロック数式が開き、文中で `$$a+b$$` と打ち切るとその場でインライン数式になります（コードブロックの ` ``` ` と同じ入力ルールです。Backspace で取り消せます）。**単独の `$…$` は数式になりません** — `$100〜$200` のような通貨表記を数式と誤読しないためです（[アーキテクチャと ADR](../architecture.ja.md) の「インライン数式」の ADR）。TeX の構文エラーはメッセージで表示し、**ソースはそのまま保持**します
- コードブロックのシンタックスハイライト: ` ```js ` のように**言語を指定したコードブロック**が、プレビュー上で色分けされます（highlight.js の主要 37 言語を拡張に同梱・完全オフライン）。**HTML / PDF 出力と同じ言語セット・同じ配色**なので、画面で色が付くものは出力にも同じ色で出ます（**言語を書いていないコードブロックは色を付けません** — 中身から言語を推測すると、ただの文章が色分けされてしまうため。出力側も同じ規則です）。色は VS Code のテーマ（ライト / ダーク / ハイコントラスト）に追従します。**Markdown は 1 バイトも変わりません**（表示だけの色付けなので、入力中もコードはそのまま編集できます）。色付けが不要なら設定 `glyphcove.preview.highlight` を off にしてください（HTML / PDF 出力側は `glyphcove.html.highlight`）
- コードブロックにする / 戻す: **複数行を選んでツールバーの「{ }」**を押すと、選んだ行が**改行で連結された 1 つのコードブロック**になります（1 行ずつ別々のコードブロックにはなりません）。**コードブロックの上で押すと 1 行 1 段落の本文に戻ります**。選択に表・水平線・保護中のブロック（生 HTML や front matter）が混ざっている場合と、**リスト項目をまたいでいる場合は何も起きません**（Markdown に表現できない入れ子になるため）。連結すると**太字などの装飾は落ちます**（コードブロックは装飾を持てないため）が、**画像・保存された `<br>`・インライン数式は書いたままの文字として残ります**（黙って消しません）。戻すときは**空行と字下げが落ちます**（段落はどちらも持てないため）
- コードブロックから抜ける: コードブロックの中では Enter が改行になるため、**抜けるには Ctrl+Enter** を押します。**文書の最後がコードブロック・数式・図・表・水平線・生 HTML・front matter のときは、その下に「＋ 段落を追加（Ctrl+Enter）」という薄い枠**が出ます。クリック（または Tab で移動して Enter / Space）すると本文の段落が 1 つ増えます。**枠が出ているだけでは Markdown は 1 バイトも変わりません**（押して追加した空の段落もファイルには書かれません）
- Word のコードブロックの貼り付け: **Word でコードブロックの段落をコピーして貼り付けると、コードブロックとして入ります**。Word にはコードブロックという概念が無いため、**段落スタイルの書体から判断**しています — クリップボードの `<style>` にある段落スタイル（`p.CodeBlock` など）のうち、**名前の付いたスタイルで、かつ書体が欧文の等幅フォント（Consolas / Courier New など）のもの**だけをコードと見なし、**連続する段落は 1 つのコードブロックにまとめます**。字下げもそのまま入ります。**本製品の Markdown → Word 出力を Word で開いて戻す場合が本命の使い道**で、**他の人が作った Word 文書では当たらないことがあります**（スタイル名が `a0` のような名前になっている、そもそも段落スタイルを使わずに書体だけ変えている、など）。**日本語の等幅フォント（ＭＳ ゴシック等）はコードの判断に使いません** — 日本語文書では本文にも使われる書体なので、文書まるごとがコードになってしまうためです。**1 語だけ等幅の段落**（文中の `npm run build` など）は本文のままです。**Excel からの貼り付けは一切変わりません**
- コードのコピー: プレビューのコードブロックにマウスを載せると右上に**「コピー」ボタン**が現れ、押すとコードだけがクリップボードに入ります（フェンス記号や言語名は含みません）。成功すると 1.5 秒「コピーしました」と表示します（コピーできなかったときは「コピーできませんでした」と表示し、成功を装いません）。Mermaid / PlantUML の図のブロックには付きません（図はクリックすればソースが開けます）。表示だけの機能なので Markdown は変わりません
- 字数カウント: **ツールバーの「字数」ボタン**を押すと、**和文の字数・欧文の語数・読了時間**（和文 500 字/分＋欧文 200 語/分、切り上げ・最低 1 分）がその場に表示されます。数えるのは**本文のみ**で、コードブロック・数式・図・保護中のブロック（生 HTML や front matter）は含みません。**押したときだけ**数えるので、大きな文書でも編集が重くなりません。もう一度押すか、Esc か、他の場所をクリックすると閉じます
- **Office 用にコピー**: **ツールバーの「Office」ボタン**でコピーすると、Word / PowerPoint に**書式のまま**貼り付けられます（**何も選ばずに押したときは文書全体**、選んであればその範囲だけ）（表の罫線・コードの等幅・引用の左罫つき）。メモ帳などに貼れば**元の Markdown がそのまま**入ります（クリップボードに 2 通りの形を同時に載せています）。**画像は `file:///` の絶対パスで参照**するので、貼り付け先が取り込みます（**base64 では埋め込みません**）。⚠ **貼り付け先は Office のデスクトップ版のみ**です（Web 版・Outlook Web では画像が解決されません）。**図（Mermaid / PlantUML）と `.svg` 画像は PNG にして貼り付けます**（Word は貼り付けた SVG を描けないため）。PNG は**一時ファイル**として書き出し、**次のコピーのとき**と**VS Code を閉じるとき**に消します（貼り付ける前に消すとWord が読めないので、その場では消しません）。⚠ **文書がホスト名を指定した図（`//サーバー/…` や `file://サーバー/…`）は読みません** — 文書を開いてコピーを押しただけで、その相手へ接続してしまうためです（共有フォルダに置いた文書からの相対参照は今までどおり読みます）。⚠ **描けなかった図は断り書きに置き換え、件数をボタンに出します**（Edge / Chrome が無い、PlantUML の Java が無い、など）。文書先頭の front matter（覚書）は貼り付けません。**保存していない文書ではコピーできません**（画像の場所が決まらないため）
- 書式ツールバー＋Markdown入力ルール（`#`＋空白→見出し、`-`＋空白→リスト、`**x**`→太字、`$$`→数式 など。Backspaceで取り消し）
- ショートカット: Ctrl+B / Ctrl+I / Ctrl+E（コード）/ Ctrl+Shift+X（取り消し線）/ Tab・Shift+Tab（リスト階層）/ Shift+Enter（ハードブレーク）
- **原文を壊さない設計**: 未編集ブロックはバイト単位で不変（Git差分は編集箇所のみ）。表・HTML・脚注・参照リンク等の未対応構文は保護中のブロックとして完全保全
- Undo/Redo・保存はVS Codeネイティブ統合。外部変更は自動検知して再同期（未反映のプレビュー編集はステータスバーで破棄警告）
- 日本語IMEの変換中は同期を保留（合成を壊さない）
