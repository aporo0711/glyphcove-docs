# Preview editing (WYSIWYG)

**日本語**: [editing.ja.md](editing.ja.md)

- How to open it: right-click a `.md` file → **Open in preview editor** (Explorer / editor tab; in the command palette it is "GlyphCove: Open in preview editor")
- Editable: paragraphs, headings, **bold**, *italic*, `code`, ~~strikethrough~~, links, bulleted / numbered / task lists (nesting supported), block quotes, code blocks, horizontal rules, and **tables** (insert, add and delete rows and columns, column alignment, Tab to move between cells)
- Shortcuts: **Ctrl+B** (bold) / **Ctrl+I** (italic) / **Ctrl+E** (inline code) / **Ctrl+Shift+X** (strikethrough) / **Ctrl+A** (select all). Of these, **Ctrl+B, Ctrl+E, Ctrl+Shift+X and Ctrl+A collide with VS Code's own shortcuts** (open and close the side bar / open a file / the Extensions view / select all), so **the editor takes them only while the GlyphCove editor is selected** and VS Code's own action does not happen (when another editor or panel has the focus, everything is as before). If that assignment gets in your way, search for `glyphcove.keepShortcutInEditor` in VS Code's "Keyboard Shortcuts" and remove it
- Toolbar: **the link input box appears only when you press 🔗**, and **the table buttons appear only when the cursor is in a table** (so that they do not narrow the area for your text)
- Find and replace: **Ctrl+F finds, Ctrl+H replaces** (the 🔍 button on the toolbar opens it as well). Match case, whole word and regular expression can be toggled, F3 / Shift+F3 (or Enter / Shift+Enter) move to the next and previous match, and Esc closes it. **Matches inside a protected block are shown but not replaced** (how many were skipped is reported). Replace all can be undone in a single Undo. In regular expression mode, `$1` and `$&` can be used in the replacement text
- Table of contents (outline): **hidden by default**. Press **≡** at the left end of the toolbar and a list of the headings appears on the left; **clicking one moves to that heading**, and the current position is highlighted as you scroll. Press it again to close it. To start with it open, turn the `glyphcove.outline.show` setting on (VS Code's standard "Outline" view is for text editors only and is empty for this editor)
- Opening a link: **Ctrl+click** (Cmd+click on macOS) moves within the document for `#heading`, opens `./other.md` in GlyphCove, and opens `http(s)` / `mailto:` in your default browser or mail client. A normal click still just moves the cursor (so that the link text can be edited). **While Ctrl is held, the mouse cursor over a link becomes a pointer (a hand)** — the same signal VS Code's own editor gives (while it is not held the text cursor stays, because a plain click does not mean "open")
- Link checking: **broken links in the document open in the preview are reported in the Problems panel** — relative link targets and image files that do not exist, `#heading` anchors that are not in the document, `#heading` anchors that are not in the linked `.md` (warning), and **bare absolute paths** (writing `D:/img/x.png`, for example, because the image then does not appear in HTML output; information). **Only the open document** is checked; the workspace as a whole is not scanned. It updates about 0.5 seconds after an edit and disappears when the document is closed. If you do not need it, turn the `glyphcove.diagnostics.links` setting off
- Setting a link: **select some text and press 🔗 on the toolbar** and a URL input box opens (the box shows what the link will be applied to). Enter confirms, Esc cancels. If you press it without a selection, the URL you type is inserted as the link text as it is. Pressing 🔗 while on a link removes the link
- Editing front matter: the YAML wrapped in `---` at the top of the document is shown as a protected card, but **the "Edit" button on the card opens the raw YAML for editing as it is** (Ctrl+Enter saves, Esc cancels). Because it is the raw YAML and not a key/value form, **both the comments and the order of the keys are kept as they were**. The save can be undone in a single Undo
- Images: images given as a relative path or a `data:` URI are really shown in the preview. "Insert image" on the toolbar opens a file picker (for a file outside the workspace, copying it next to the document is recommended). **External `http(s)` images are not loaded** (a placeholder is shown; by design, opening a document causes no outside traffic)
- Pasting tables: **a table copied from Excel or Word can be pasted as a table**. Several lines inside a cell are kept as a line break within the cell (`<br>`). **Merged cells in a Word table are split when pasting**, and the value goes into the top-left cell of the merged range (because a Markdown table has no way to express a merged cell; a notification appears when they are split; a table nested inside a table is expanded to text). **Tables on a web page paste the same way** — merged cells are expanded by the same rule as Word, so even a table with `colspan` / `rowspan` does not end up one column out of line
- Pasting box-drawn tables: **pasting the text of a table drawn with box-drawing rules turns it into a table** — the **single-line box-drawing pieces** of `┌─┬─┐`, the ASCII rules of `+---+` (terminal output from `mysql` / `psql` and the like), and **a Markdown table copied as plain text** are handled. **Cells are read by splitting on the vertical lines** (column positions are not counted — a single Japanese character mixed in is enough to throw the columns out of alignment). **Double lines, heavy lines, rounded rules, merged cells and broken grids are not turned into a table and paste as text, as before** (repairing them by guesswork would silently rewrite the original text)
- Pasting CSV / TSV: **pasting comma-separated or tab-separated text turns it into a table** (copying from a `.csv` opened in the editor, pasting a log, and so on). Quoted values (`"a,b"`) and line breaks inside a cell are handled too. **The test is on the strict side**: it becomes a table only when there are two or more lines, every line has the same number of columns, and there are two or more columns (for commas it also requires three or more lines or three or more columns — two lines and two columns such as "yes, no" cannot be told apart from prose). When the conditions are not met, **it pastes as text, as before**. **A copy from Excel does not go through this path** (Excel puts the table itself on the clipboard as well, and that is what is used)
- Pasting and dragging images: screenshots and image files can be inserted with Ctrl+V or by dropping them. **Files are always saved into `<document-name>_images/`**, and only the path is written into the Markdown (no base64 is generated). An image dropped from inside the workspace is referenced where it is, without being copied. **When dragging from VS Code's Explorer (the tree), hold Shift while you drop** (by VS Code's design, a drop without Shift is an "open the file" action)
- Editing diagrams (draw.io): paste a `*.drawio.svg` / `*.drawio.png` that draw.io saved as an **editable diagram**, and **a double-click on the image in the preview opens the draw.io editor beside it** (the [Draw.io Integration](https://marketplace.visualstudio.com/items?itemName=hediet.vscode-drawio) extension is required; if it is not installed, a message says so). Saving **updates the diagram in the preview automatically**. Double-clicking any other image opens it in VS Code's default editor (the image preview, or text for `.svg`)
- Pasting shapes (stencils): **select a shape in draw.io, copy it, and press Ctrl+V in the preview**, and a `Stencil.drawio.svg` holding the diagram is created in `<document-name>_images/` and inserted as an image (previously a `%3CmxGraphModel…` string was inserted instead). If the Draw.io Integration extension and Edge/Chrome are installed, **pasting alone draws the actual diagram automatically** (the draw.io build bundled with that extension is run in the background in a headless browser; the first time can take a few seconds to start). Without the extension or a browser, or when drawing fails, the placeholder message stays, and **double-clicking it, opening it in draw.io and saving draws it** (from then on it works like "Editing diagrams (draw.io)" above)
- Resizing images: select an image and drag one of the corner handles to change its width (the aspect ratio is kept). An image with a size is saved in the GitHub-compatible `<img src width>` form (because Markdown has no standard size notation; in DOCX conversion it counts as inline HTML and becomes text, with a warning). ⚠ **The handles respond to dragging only, so the width cannot be changed with the keyboard alone** (WCAG 2.2 2.1.1 / 2.5.7 / 2.5.8 — see [Known normalisations and limitations](limitations.md)) — to set a width as a number, press **"Show source"** on the toolbar to open the Markdown beside the preview and edit the `width` in `<img src="..." alt="..." width="480">` by hand (the preview shows that form as a real image as it is)
- Resizing an embedded (base64 / `data:` URI) image writes it out to the `<document-name>_images/` folder automatically and replaces it with a file reference (**policy: images are kept as external files and no base64 is generated**). After it is written out, only the path and the size are left in the Markdown
- Automatic heading numbering: when you rewrite the number at the start of a heading (`1.` / `1.1`), **the numbers of the headings that follow are updated automatically** (change `2.` to `5.` and the ones after it become 6, 7 …, and the sub-headings are renumbered `5.1`, `5.2` as well). Deleting a heading also closes up the ones that follow. The heading you are editing and the headings before it are not rewritten. Only **headings that already have a number** are touched: a heading without one, such as "Introduction", and a form such as "Chapter 2 …" are left alone. The **№ button** on the toolbar can also renumber the whole document (the first number is respected as the starting point). If you do not need the automatic updating, turn the `glyphcove.numbering.auto` setting off
- Drawing Mermaid diagrams: a ` ```mermaid ` code block **is shown as a diagram in the preview** (mermaid is bundled with the extension and is fully offline; only the first time takes a moment while it loads). **Click the diagram, or move the cursor into the block, and the source opens**; editing it updates the diagram live (move the cursor out and only the diagram is shown again). On a syntax error the error message is shown and **the source is kept as it is** (the last diagram that worked stays, dimmed)
- Diagrams are drawn **once they come near the screen**: Mermaid / PlantUML diagrams **are drawn at the point where you are about to scroll to them** (read ahead from 300px before the screen). Even in a document full of diagrams, they are no longer all drawn the moment it opens, and the first screen appears sooner. **Height is reserved where a diagram has not been drawn yet**, so the text does not jump when the drawing catches up. A diagram edited off-screen is redrawn **once, with the latest source, when it becomes visible** (math is light because it uses KaTeX, so it is drawn immediately, as before)
- Drawing PlantUML diagrams: ` ```plantuml ` / ` ```puml ` code blocks are shown as diagrams and update live in the same way (`@startuml` is not needed — the fence language alone is enough; explicit blocks such as `@startmindmap` also work as they are). Drawing needs **Java and plantuml.jar** — if the [PlantUML extension (jebbs.plantuml)](https://marketplace.visualstudio.com/items?itemName=jebbs.plantuml) is installed, **the jar it bundles is reused automatically** (the `glyphcove.plantuml.jarPath` / `javaPath` settings can also point at them explicitly). Without them, a message says so and nothing more, and the source can still be edited. Layout uses smetana, which needs no Graphviz (class diagrams and the rest are drawn without dot). A syntax error is shown as **a message with a line number, not an error image**
- GitHub Alerts: a block quote beginning with `> [!NOTE]` / `> [!TIP]` / `> [!IMPORTANT]` / `> [!WARNING]` / `> [!CAUTION]` is shown as **a coloured callout for each kind**. In the preview the `[!NOTE]` text stays there, editable (the Markdown does not change by a single byte), and when the document is converted to HTML / PDF / Word it becomes a callout with a background colour and a left rule for each kind, headed **in the language of the document** — `Note` / `Tip` / `Important` / `Warning` / `Caution` in an English one, `ノート` / `ヒント` / `重要` / `警告` / `注意` in a Japanese one. Editing inside the callout keeps the `> [!NOTE]` line in exactly the same form, so the document still displays correctly when it is opened on GitHub or elsewhere
- Drawing math: a line wrapped in `$$` **is shown as a formula in the preview** (KaTeX is bundled with the extension and is fully offline). It works like the diagrams: **click the formula, or move the cursor into the block, and the source (TeX) opens**; editing it updates the formula live. Inline math written in the middle of a paragraph is **wrapped in the same `$$`**, as in `$$a^2 + b^2 = c^2$$`, and clicking it opens a small input box where the TeX can be corrected (Enter confirms / Esc cancels / emptying it deletes the formula). To write a new one, use **∑ on the toolbar** for a block formula, or type `$$` at the start of a line and a block formula opens; type `$$a+b$$` in the middle of a line and it becomes an inline formula on the spot (the same input rule as ` ``` ` for a code block; Backspace undoes it). **A single `$…$` does not become a formula** — so that currency such as `$100〜$200` is not misread as math (the "Inline math" ADR in [Architecture and ADRs](../architecture.md)). A TeX syntax error is shown as a message and **the source is kept as it is**
- Syntax highlighting in code blocks: **a code block with a language given**, as in ` ```js `, is coloured in the preview (the 37 main languages of highlight.js are bundled with the extension and are fully offline). **The language set and the colours are the same as in HTML / PDF output**, so whatever is coloured on screen comes out in the same colours (**a code block with no language written is not coloured** — guessing the language from the content would colour plain prose; the output side follows the same rule). The colours follow the VS Code theme (light / dark / high contrast). **The Markdown does not change by a single byte** (it is colouring for display only, so the code can still be edited while you type). If you do not need the colouring, turn the `glyphcove.preview.highlight` setting off (for HTML / PDF output it is `glyphcove.html.highlight`)
- Making a code block and turning one back: **select several lines and press { } on the toolbar** and the lines you selected become **one code block with the lines joined by newlines** (not a separate code block per line). **Pressing it while on a code block turns it back into body text, one paragraph per line.** When the selection contains a table, a horizontal rule or a protected block (raw HTML or front matter), and **when it spans list items, nothing happens** (the nesting could not be expressed in Markdown). Joining the lines **drops decoration such as bold** (a code block cannot carry decoration), but **images, saved `<br>` and inline math are left as the characters that were written** (nothing is deleted silently). Turning it back **drops blank lines and indentation** (a paragraph cannot carry either)
- Leaving a code block: inside a code block Enter inserts a newline, so **to leave it press Ctrl+Enter**. **When the document ends with a code block, math, a diagram, a table, a horizontal rule, raw HTML or front matter, a faint frame reading "+ Add a paragraph (Ctrl+Enter)" appears below it.** Clicking it (or moving to it with Tab and pressing Enter / Space) adds one body paragraph. **While the frame is only showing, the Markdown does not change by a single byte** (the empty paragraph added by pressing it is not written to the file either)
- Pasting a code block from Word: **copying a code-block paragraph in Word and pasting it puts it in as a code block**. Word has no concept of a code block, so **the decision is made from the font of the paragraph style** — of the paragraph styles in the clipboard's `<style>` (`p.CodeBlock` and the like), only **those that have a name and whose font is a Western monospaced font (Consolas / Courier New and so on)** count as code, and **consecutive paragraphs are joined into one code block**. Indentation comes in as it is. **The intended use is opening this product's Markdown → Word output in Word and bringing it back**, and **it may not match in a Word document someone else made** (the style name is something like `a0`, or no paragraph style was used at all and only the font was changed). **Japanese monospaced fonts (ＭＳ ゴシック and the like) are not used to decide what is code** — in a Japanese document they are used for body text too, so the whole document would become code. **A paragraph with only one monospaced word** (`npm run build` in the middle of a sentence, for example) stays body text. **Pasting from Excel does not change at all**
- Copying code: put the mouse over a code block in the preview and a **"Copy" button** appears at the top right; pressing it puts the code alone on the clipboard (the fence markers and the language name are not included). On success it shows "Copied" for 1.5 seconds (when the copy failed it shows "Copy failed" and does not pretend to have succeeded). It is not attached to Mermaid / PlantUML diagram blocks (a diagram opens its source when you click it). It is a display-only feature, so the Markdown does not change
- Word count: press the **"Words" button on the toolbar** and **the number of Japanese characters, the number of Western words, and the reading time** (Japanese at 500 characters/minute plus Western at 200 words/minute, rounded up, minimum 1 minute) are shown on the spot. Only **body text** is counted: code blocks, math, diagrams and protected blocks (raw HTML and front matter) are not included. It counts **only when you press it**, so editing does not become heavy even in a large document. Press it again, press Esc, or click somewhere else to close it
- **Copy for Office**: copy with the **"Office" button on the toolbar** and it can be pasted into Word / PowerPoint **with the formatting kept** (**the whole document when you press it with nothing selected**, or just that range if there is a selection) (table rules, monospaced code, block quotes with a left rule). Paste it into Notepad or the like and **the original Markdown** goes in (both forms are put on the clipboard at once). **Images are referenced by `file:///` absolute path**, so the destination takes them in (**they are not embedded as base64**). ⚠ **The destination must be a desktop version of Office** (the web versions and Outlook Web do not resolve the images). **Diagrams (Mermaid / PlantUML) and `.svg` images are turned into PNG for pasting** (because Word cannot draw a pasted SVG). The PNGs are written out as **temporary files** and deleted **at the next copy** and **when VS Code closes** (deleting them before you paste would leave Word unable to read them, so they are not deleted on the spot). ⚠ **Diagrams in the document that name a host (`//server/…` or `file://server/…`) are not read** — merely opening the document and pressing copy would connect to that machine (relative references from a document in a shared folder are read as before). ⚠ **A diagram that could not be drawn is replaced with a note, and the number of them is shown on the button** (no Edge / Chrome, no Java for PlantUML, and so on). The front matter at the top of the document (the memo) is not pasted. **A document that has not been saved cannot be copied** (because the location of the images cannot be determined)
- A formatting toolbar plus Markdown input rules (`#` + space → heading, `-` + space → list, `**x**` → bold, `$$` → math, and so on; Backspace undoes them)
- Shortcuts: Ctrl+B / Ctrl+I / Ctrl+E (code) / Ctrl+Shift+X (strikethrough) / Tab and Shift+Tab (list level) / Shift+Enter (hard break)
- **Designed not to break the original**: blocks you did not edit are unchanged byte for byte (the Git diff covers only what you edited). Unsupported syntax such as tables, HTML, footnotes and reference links is fully preserved as a protected block
- Undo/redo and saving are natively integrated with VS Code. Changes made outside are detected automatically and re-synced (preview edits not yet applied get a discard warning in the status bar)
- Syncing is held while a Japanese IME conversion is in progress (so that composition is not broken)
