| MD → HTML | ✅ | スタンドアロン/フォルダ出力、TOC、ハイライト、画像埋め込み、サニタイズ、**文書の題**（front matter の `title:` / `タイトル:` → 最初の見出し → `Document` の順。YAML として読むので折り返した題や行末コメントも正しく扱い、**Word / Excel への変換と同じ題**になります。YAML が壊れていれば警告して最初の見出しへ倒します）、**印刷時のヘッダー/フッター**（PDF と同じ設定・同じ書式。**画面の見た目は変わらず、ブラウザで印刷したときだけ**出ます）、**Mermaid図**（既定はSVG事前変換。`glyphcove.html.mermaid` で JS同梱 / コードのまま に変更可）、**PlantUML図**（既定はSVG事前変換。`glyphcove.html.plantuml` で コードのまま に変更可。JS同梱方式はPlantUMLには存在しません）、**数式**（KaTeXで描画。スタンドアロン出力にはCSSとフォントを埋め込むので単体ファイルのまま持ち歩けます）、**改ページ**（`<!-- pagebreak -->`。画面では何も表示せず、ブラウザの印刷とPDF化のときだけ改ページします） |

| MD → DOCX | ✅ ロスあり | 見出し/表/リスト/コード/画像/引用/脚注。**参照テンプレート（.docx）の書式取り込み**（`glyphcove.docx.template`）、**目次フィールド**（見出しは文書の言語に合わせて「目次」/ `Contents`）、**図表番号の自動採番**、ヘッダー/フッターとページ番号、用紙・向き・既定フォント。**コードブロックはプレビュー・HTML と同じ配色でハイライト**、リンクは Word のハイパーリンク書式、タスクリストは `☐`/`☑`、**GitHub Alerts は色付きの囲み**。画像は png/jpg/gif/bmp と data URI に対応。数式・生HTMLは出力できないので**テキスト化して警告**（`DOC004` / `DOC005`）。**Mermaid/PlantUML の図と `*.drawio.svg` を画像として埋め込み**（`glyphcove.docx.diagrams` = `svg`（既定・ベクタ＋PNGフォールバック）/ `png` / `off`。描画には Edge または Chrome が必要で、無い場合はコードブロックのまま＋警告） |
| DOCX → MD | ✅ ロスあり | 構造優先（mammoth）。見出し/表/リスト/強調に加え、**引用・インラインコード・コードブロック・タスクリスト（`☐`/`☑` → `- [ ]`/`- [x]`）**も復元。画像は `<出力名>_images/` へ書き出し（base64 埋め込みなし）。**警告はその文書を実際に調べた結果だけ**を出します（変更履歴・コメント・ヘッダー/フッター・Word の数式・埋め込みオブジェクトがあるときだけ。**テキストボックスの文字は変換されます**）。**品質レポート（JSON/MD）**に、Markdown へ出せなかったヘッダー/フッターとコメントの本文を書き出します（`glyphcove.docxToMd.qualityReport`） |
| MD表 → XLSX | ✅ ロスあり | 表ごとにシート化。**表ではないもの（本文・見出し・コード・画像・図）は格子ではなくメタシートへ回ります**。「ロスあり」はこれを指します。シート名正規化、数式注入対策、**セルの型推論**（数値/ISO日付/％/通貨は実データ型。先頭ゼロ・16桁以上のID・曖昧な日付は文字列のまま保持して警告）、ヘッダー行固定・オートフィルタ・列幅自動調整、**メタシート**（`_Metadata` / `_Document` / `_Code` / `_Assets` / `_Diagrams` / `_Warnings`）。セル内改行（`<br>`）はExcel側の改行として往復します。**`report` モードは段落・リスト・引用・脚注の中の太字/斜体/取消線/インラインコードを Excel のリッチテキスト（run のフォント）として書く**ので、Markdown へ読み戻したときに `**` `*` `~~` `` ` `` が戻ります（平文化していた頃は 1 世代目で失われていました） |
| HTML → MD | ✅ ロスあり | 構造優先。Web からの貼り付けと同じエンジンで、**サイトの飾り（ナビゲーション・ヘッダー・フッター）とスタイル・スクリプトは除去**し、本文だけを変換します（`.html` / `.htm`。丸ごと保存したページでも `<title>` が本文に混ざりません）。表は GFM の表に再構成（**結合セルは展開** — 値は左上に残り、覆われていた位置は空セル。**セル内の入れ子の表は外側のセルの文字に平坦化**。どちらも警告付き）、表の `<caption>` は表の直前の段落へ。`&lt;application&gt;` のような**タグに見える本文はタグに戻さず文字のまま**残します。画像は**コピーも埋め込みもしません** — 参照は書かれたまま残し、出力先が HTML と別のフォルダのときは相対参照がずれることを警告します。ファイルは UTF-8 として読みます（別の文字コードを宣言している文書は警告） |
| DOCX → HTML | ✅ ロスあり | **直接変換（Markdown を経由しません）**。DOCX → MD が途中で作っている構造 HTML をそのまま出力し、**表の結合セルを colspan/rowspan のまま保持**します。見出し/リスト/引用/コード/タスクリストのスタイル対応は DOCX → MD と同じ。画像は `<出力名>_images/` へ書き出し（base64 埋め込みなし）。下線・文字色・フォント・段組み・ページ設定などの見た目は保持されません。棚卸し警告（変更履歴・コメント・ヘッダー/フッター・Word の数式・埋め込みオブジェクト）と**品質レポート（JSON/MD・出力へ出せなかったヘッダー/フッターとコメントの本文を収録）**も DOCX → MD と同じ帳簿です |
| XLSX → HTML | ✅ ロスあり | **直接変換（Markdown を経由しません）**。シートを格子のまま HTML の表にし、**結合セルを colspan/rowspan で保持**します（Markdown 経由ではこれが失われます）。値は Excel の見た目（日付・％・`QA-001` などの表示形式）、ハイパーリンクは `<a>`、シートの画像は `<出力名>_images/` へ書き出し（base64 埋め込みなし）、非表示シートは見出しに印、数式は計算値＋警告。図形・グラフ・ピボット・セルの色や罫線は変換されません |
| XLSX → MD | ✅ ロスあり | シート選択可。**結合セルは左上だけに値を出力**（覆われたセルは空）、**値の無い行・列は表の外側から除去**、**表の部分だけが表になり、表題・説明文・手順書などは本文の段落へ**（空行で区切り。本製品の MD→XLSX 出力はシート全体が 1 つの表のまま往復します）、**日付・パーセント・通貨・ユーザー定義の表示形式は Excel の見た目で出力**（`0.35`→`35%`、`1`→`QA-001`。日付は ISO）、**シートの画像は `<出力名>_images/` へ書き出し**（base64 埋め込みなし。表の後ろにまとめ、alt に位置を記載）、ハイパーリンクは `[文字](URL)`、非表示シートは見出しに印（文書の言語に合わせて「（非表示シート）」/ ` (hidden sheet)`）を付けて変換。**セル内の一部だけに掛かった太字/斜体/取消線/等幅は `**` `*` `~~` `` ` `` として復元**（セル全体に掛かっている書式は「そのセルの見た目」なので装飾にしません。引用の斜体グレーが `*…*` に化けないのはこのため）。結合セル/数式/非表示シートは警告付き。**品質レポート（JSON/MD）**（`glyphcove.xlsxToMd.qualityReport`） |

- **2 段変換（Markdown 経由）**: 上の表の X → MD と MD → Y を自動で連結し、**PDF → Word / Excel / HTML、Word → PDF / Excel、Excel → PDF / Word、HTML → PDF / Word / Excel** の 10 通りも選べます。形式の選択肢には「**PDF → Word（Markdown 経由・レイアウトは再現しません）**」のように出ます。名前のとおり、**引き継がれるのは中間の Markdown に残る文書の構造で、元のレイアウトは再現しません**（両段のロスと警告がそのまま適用されます）。変換結果には**両段の警告をまとめた品質レポート**が付き、冒頭に 2 段で変換したことを明記します（第 1 段の品質レポートも同じファイルに収録するので、途中のファイルを残さなくても失われた内容を確認できます）。**Word → HTML と Excel → HTML はこの経路では提供しません**（Markdown を挟むと、両端が表現できる結合セルなどが失われるため。上の表の**直接変換**が受け持ちます）
- 一括変換: 複数選択・フォルダ再帰、上書き規則（スキップ/上書き/連番）、並列数・タイムアウト・失敗時継続の設定、キャンセル（壊れた成果物を残さない）、JSON＋人間可読ログの自動保存
- **複数の Markdown を 1 つの PDF / HTML / Word / Excel にまとめる**: 2 つ以上の `.md` を選んで変換すると「1 つのファイルにまとめますか？」を聞きます（**フォルダ一括でも同じ**）。並びは**ファイル名の自然順**（`2-x.md` → `10-x.md`。単純な文字コード順だと `10` が `2` より前に来ます）で、**表示言語にも端末の地域設定にもよりません**（同じファイルなら誰が変換しても同じ順に並びます）。出力名は**親フォルダ名を既定にした入力欄**で決めます。**見出しはそのまま連結**するので、各ファイルがそのまま章になります。境目は **PDF・Word が改ページ、HTML が区切り線**（Excel はシートで分かれます）。まとめるときは以下を自動で調整します
  - **画像の相対パスはファイルごとの位置で解決**します（`a/doc.md` と `b/doc.md` の `![](img/x.png)` は別の絵として扱われます。素朴に本文をつなぐと片方がもう片方の絵に化けます。**base64 埋め込みはしません**）
  - **脚注 `[^1]` と参照リンク `[x]: …` はファイルごとに振り直します**（CommonMark は同じ名前の定義を**最初のものだけ**採用するので、2 つ目のファイルのリンク先が黙って入れ替わります）
  - **同じ見出しへのページ内リンク**（`[戻る](#概要)`）は、そのファイル自身の見出しを指すように付け替えます
  - **front matter は先頭のファイルのものだけ**を文書のメタデータにし、2 つ目以降は**捨てたことを警告で報告**します（黙って本文に出しません）
  - **コードブロックとインラインコードの中は書き換えません**（Markdown の書き方を説明した文書がそのまま残ります）
  - **Excel は `report` モードが「ファイルごとに 1 シート」**（シート名はそのファイルの最初の見出し）、**`data` モードはシート名に文書の連番**（`1-売上` `2-売上`）。同じ見出しの表が複数のファイルにあると、連番が無いと `売上_2` になって由来が分からなくなるためです（ファイル名を接頭辞にするとシート名の 31 文字上限を食い潰すので採っていません）
  - 変換ログには**どのファイルからできた 1 件か**が並びます
  - 既知の限界: **UNC パス（`\\server\share\…`）にある文書の画像は、まとめると Word / Excel に埋め込めません**（`IMAGE_UNC_BLOCKED` で報告。PDF / HTML は埋め込めます）
- **文書の区切り**: `<!-- md2office: docbreak -->`（`<!-- docbreak -->` も可）と書くと、**Excel の `report` モードがそこでシートを分けます**（まとめる機能はこの印を自動で入れています）。改ページ（`<!-- pagebreak -->`）とは別の印で、Word・PDF・HTML では何も起きません
- **改ページ**: 本文に `<!-- pagebreak -->`（`<!-- md2docx: pagebreak -->` / `<!-- md2office: pagebreak -->` も同じ）と書くと、**DOCX・PDF・HTML の印刷**でそこから次のページになります。HTML では `<div class="ms-page-break"></div>` として出力し、**画面上は何も表示しません**（`glyphcove.html.standalone` を off にした本文だけの出力にはスタイルが付かないため、埋め込み先で `break-after: page` を指定してください。その旨を警告で報告します）。XLSX には改ページの概念がないため無視されます。**行の途中に書いても効きます**（`本文。<!-- pagebreak -->続き。` のように書くと、その位置で段落を割って改ページします。プレビューで段落の末尾に打つと自然にこの形になります）。**強調やリンクの中**（`**前<!-- pagebreak -->後**`）に書いた場合も、装飾を両側に残したままその位置で割ります。**見出しの中**に書いた場合は見出しを割らず（目次に偽の項目が増えるため）、印が見出しの先頭なら見出しの直前、それ以外なら直後で改ページします。**表のセルの中では改ページできません**（Word のセルは 1 ページに収まる単位）。無視したことを警告（`DOC006` / `MD_PAGE_BREAK_IN_TABLE`）で報告します
- スキャンPDF（テキストレイヤーなし）は**正直に未変換として報告**します（OCRエンジンを同梱していないため、画像から文字を読むことはできません）。**文字が 1 つでもあるページは、少なくてもその文字を本文に出します**（章扉・表紙・図だけのページは 10 文字前後しかありませんが、見出しはそこにあります）。20 文字に満たないページは `PDF_SPARSE_PAGE` で「スキャンの可能性がある／このページの画像は取り出していない」ことを併せて報告します
- **ページごとに繰り返される柱（ヘッダー・フッター）とページ番号、斜めの透かしは本文から外します**（`PDF_RUNNING_TEXT_SKIPPED` で件数と例を報告。黙って消しません）。本文に混ざると読みにくいだけでなく、**本製品で柱や透かしを付けて出力した PDF を読み戻すと全ページに混入する**ため入れました。判定は**位置だけでは決めません** — 「ページの上下の余白帯にある」「そのページのいちばん外側の行である」「同じ高さ・同じ揃えで、同じ形の文字が文書の 1/3 以上のページに出る」の**すべて**が揃ったときだけ外します（ページ番号のように数字だけが変わるものは同じ形と見ます）。**外すのは上下それぞれ 1 行だけ**なので、柱のすぐ下にある見出しは残ります。透かしは**斜め（20〜70度）かつ本文の 2 倍以上の大きさ**の文字だけを外すので、図の中の縦書きラベル（90 度）や図の注記は残ります
- **タグ付き PDF は文書構造の記録から復元します**（`PDF_STRUCT_RESTORED` で報告）。タグ付き PDF には「この範囲は見出し・箇条書き・引用・表」という構造そのものが記録されており、本製品の MD→PDF 出力・Word の PDF 出力・LaTeX の論文の多くが該当します。見出しの階層・箇条書き（記号が図形で描かれていてテキストに残っていない場合も）・**タスクリストのチェックボックス（✔ の有無は描画命令から判定。判別できなければ `- [ ]` に倒して `PDF_CHECKBOX_STATE_UNKNOWN` で報告）**・引用と GitHub Alerts（囲みのタイトル「ノート」等から `> [!NOTE]` へ）・太字/斜体/インラインコード・**取消線**（タグにも文字にも無いため、文字の上に重ねて描かれた細い矩形を描画命令から拾って重ね合わせます。見出しの下罫線・表の罫線は高さが違うので巻き込みません）・表（**折り返しセルも罫線だけの表も**タグの記載どおり。**セル内改行は `<br>` として復元**）・画像の本当の代替テキストが復元されます。タグに含まれない内容（数式など）も捨てずに位置で差し込みます。**ベクタ描画の図（Mermaid・PlantUML・draw.io など）は、ページのその領域をヘッドレスブラウザ（Edge/Chrome）上の pdf.js で描画して PNG として書き出します**（`PDF_VECTOR_FIGURE_RASTERIZED` で報告。設定 `glyphcove.pdfToMd.vectorFigures`、既定 on・`pdfToMd.images` が on のときのみ）。図の範囲は文書構造（`Figure` タグ、または図のラベルの構造木と描画命令の重なり）から求め、図の中の文字ラベルは画像に含まれるため本文には出力しません。**ブラウザが無い環境では従来どおりテキストのまま出力**し、`PDF_VECTOR_FIGURE_RASTER_FAILED` / `PDF_VECTOR_FIGURE` で正直に報告します（変換は失敗しません）。タグが「段落」しか言っていない文書・タグが本文の半分に届かないページは、以下の推定で読みます
- **数式の上付き・下付きを復元します**（タグの有無によらず。`E = mc2` → `E = mc^2`、`xmin` → `x_{min}`）。表記は TeX と同じで、1 文字はそのまま・2 文字以上は `{}` で囲みます（`10^{-7}`）。**脚注や注釈の番号は巻き込みません** — 脚注参照も「小さくて上付き」の同じ形で出るため、位置と大きさだけでは区別できないからです。指数が付く相手（数字・閉じ括弧・1〜2 文字の変数名）であること・直前が和文でないこと・リンクでないことを併せて見ます（`脚注のある文1です。` は `脚注のある文^1です。` になりません）。**分数・根号・積分・行列は対象外**です（PDF に情報が無く、数式 OCR の領域です）
- PDF→MD の見出し・段落の判定は**文書全体の統計**（本文の文字サイズ・行送り・左端）で行います。1 ページだけ極端な内容（極小の文字が並ぶ図など）があっても、他のページの読み取りは変わりません
- **2 段組み以上のページは段ごとに読み、左の段を最後まで読んでから次の段へ進みます**（`PDF_COLUMNS_REORDERED` で報告）。全幅の見出しや図のキャプションは段を分ける境目として扱うので、見出しは自分が導く段の前に出ます。**段の境目を切り出せなかったページ**は従来どおり並べ替えずに `PDF_READING_ORDER_SUSPECT` で報告します（図の中の縦の隙間を段の境目と誤ると、段落の後半がページ末尾へ飛ぶため、谷が本文の高さいっぱいに通っているページだけを段組みと見なします）
- **表は Markdown の表に組み直します**（`PDF_TABLE_RECONSTRUCTED` で報告）。**文書が罫線を引いている表は、その罫線からセルの区切りを読みます** — 縦の罫線が列の境目、横の罫線が行の境目です。罫線があれば推測が要らないので、**セルが 2 行に折り返していても 1 つのセルとして復元できます**（セル内改行は `<br>`。タグ付き PDF と同じ表現なので、Word / Excel へ変換しても改行のまま残ります）。Word のように**セルを縦中央に置く**ソフトでは、折り返したセルの隣の行番号が**その 2 行のあいだ**に来ますが、行の境目が罫線で決まるので正しく 1 行として読めます。罫線は**細い矩形として描かれている**ため、**設定 `glyphcove.pdfToMd.images` を off にすると罫線も読みません**（そのためだけに描画命令の走査を増やさないため。太字・斜体の復元と同じ理由です）。罫線の無い表は従来どおり**文字の位置からの推定**です: 列の境目は行ごとの隙間ではなく**表全体で縦に空いている帯**で決めるので、右寄せの数値で列の左端が行ごとにずれても列数を取り違えません。**段組みのページを表にしないよう、周りの行がその谷で終わっていないか**（＝ページ全体の段の境目でないか）を確かめてから組みます。列を決められなかった配置は従来どおり `PDF_TABLE_SUSPECT` で報告し、本文は文字列のまま残します。**罫線があっても次のものは罫線からは読まず、桁位置の推定に戻します**（誤って読むより正直に落とす方を選んでいます）: **セルを結合した表**（罫線が格子の途中で止まっているもの。平らな表として読むと内容が別の列に入るため、**その格子ごと使いません**）、**横に並べて置かれた表**（1 行が複数の表をまたぐため）、**外枠を引いていない表**、**段の境目を切り出せなかったページ**。数式の分数も対象外です
- **写真・画像は `<出力名>_images/` へ PNG で書き出し**、本文の元の位置に `![…](…)` として挿入します（`PDF_IMAGES_EXTRACTED` で報告。**base64 では埋め込みません**）。**この経路で取り出せるのはラスタ画像（写真・スクリーンショット）だけ**です。図形で描かれた図（Mermaid・PlantUML・作図ソフトの図）は PDF に画像として存在しませんが、**タグ付き PDF ではページの見た目から画像化して補います**（上記「ベクタ描画の図」）。次のものは書き出しません: **本文 2 行ぶんより小さい画像**（アイコン・箇条書きの記号・「画像が見つかりません」の記号。`PDF_IMAGE_TOO_SMALL`）、**透明で見えない画像**（Word 由来の PDF に多く含まれます）、**テキストレイヤーのないページの画像**（ページ全体が 1 枚の写真で、PNG にすると 1 ページ数十MBになるため。`PDF_SCAN_IMAGE_SKIPPED`）。**A4（96dpi ＝ 1123×794 画素）に収まらない画像は、収まる大きさへ縮小して書き出します**（`PDF_IMAGE_RESIZED` で報告。縦横比はそのまま・拡大はしません）。Markdown やブラウザが画像を表示する大きさは 96dpi 換算なので、それ以上の画素は表示にも印刷にも使われないままファイルと時間だけを増やすためです。元の画素のまま出すには設定 `glyphcove.pdfToMd.imageResize` を off にしてください。それでも写真の多い文書では画像フォルダーが元の PDF より大きくなることがあります（PNG は写真を JPEG ほど小さくできないため）。不要なら設定 `glyphcove.pdfToMd.images` を off にしてください
- **タグの無い PDF でも太字・斜体・取消線を復元します**（`PDF_EMPHASIS_FROM_FONT` で報告）。PDF には「ここが太字」という記録がないため**書体の名前と文字の傾きからの推定**です。実際の書体名は `getTextContent()` からは取れず（そこが返すのは sans-serif / serif / monospace の 3 種類だけ）、**描画側にしかない**ので、**画像の取り出しと同じ 1 回の走査**で読み取ります — **設定 `glyphcove.pdfToMd.images` を off にすると装飾の復元も行いません**（そのためだけに走査を増やさないため）。**日本語の斜体は「斜体の書体」ではなく文字の傾き**（同じ書体のまま行列が傾く）で、欧文は専用の書体なので、両方を見ます。**見出しと表のヘッダーには印を付けません**（大きさで既に見出しにしており、`# **見出し**` と二重になるため）。LaTeX のように書体名が `…TB`（Text Bold）/ `…TI`（Text Italic）の流儀にも対応しています
- **タグの無い PDF では、箇条書きの記号はテキストとして残っている場合だけ**復元できます。Word や LaTeX が作った PDF では `•` / `・` が残りますが、**Chromium（Edge/Chrome）で印刷した PDF は記号を図形として描く**ため、テキストからは復元できません（Chromium 印刷の PDF はタグ付きなので、実際には上記の構造復元が箇条書きを取り戻します）
