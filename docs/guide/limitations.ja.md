# 既知の正規化・制限

**English**: [limitations.md](limitations.md)

- **編集したブロックのみ** `mdast-util-to-markdown` の正規化を受けます（`_em_`→`*em*`等）。未編集ブロックは影響を受けません
- **見出しをふつうの段落に変えると、そのうしろに空行が 1 行増えます。** 見出しと次のブロックを分けていた 1 個の改行は「見出しだったから」分けられていたもので、段落には空行が要ります（空行にしないと、ファイル上は 2 つが 1 つの段落として保存され、画面と中身が食い違います）。間隔のそれ以外は変わらず、前後のブロック自体も書き換わりません
- ソフト改行の段落は編集時のみ1論理行に展開。ブロック境界の空白は `&#x20;` として保全（次の編集で自然に消えます）
- 素のURLを入力すると同期後に自動でリンク化されます（remark-gfmのautolink仕様）
- 表の貼り付けは Excel / Word / Web ページとも表のまま入ります。**Word と Web ページの表のセル結合は貼り付け時に解除されます**（GFM の表に表現が存在しないため。値は結合範囲の左上のセルへ入り、通知が出ます）。**Excel の表だけは従来どおり無変換で貼り付けます** — 現状の動作を変えないためで、Excel の結合セルは解除されずに列がずれます（既知の制限）
- **PDF の表は貼り付けでは取り込めません。** PDF から表をコピーすると、クリップボードには表の構造が載らず（多くの場合は行ごとのテキストだけ）、貼り付け側から元の桁位置を復元する手立てがありません。PDF の表が必要な場合は **PDF → Markdown 変換**（右クリック →「ファイルを変換 (Markdown / PDF / Word / Excel / HTML)」）をご利用ください。そちらは PDF の描画命令から罫線と桁位置を読み取ります
- 罫線表の貼り付けが扱うのは**単線の罫線素片と ASCII（`+ - |`）の単純な格子だけ**です。二重線（`╔═╗`）・太線（`┏━┓`）・角丸（`╭─╮`）、外枠の無い表は**表にせず素通し**します。セル結合の推測はしません
- 罫線表の**行ごとに列数が違う場合は、いちばん広い行に合わせて空セルで詰めます**（Word の結合セルを含む表を Markdown に変換したものなどが該当します）。**列を削ることはしないので、値が消えることはありません**。セルの中に縦線を入れたいときは GFM と同じく `\|` とエスケープしてください（生の `|` は区切りとして読みます）
- CSV / TSV の貼り付けは**表になる条件を満たしたときだけ**発動します（2 行以上・全行の列数が一致・2 列以上、カンマの場合はさらに 3 行以上または 3 列以上）。引用符の閉じ忘れなど**書式が崩れている場合は表にせず、文字のまま貼り付けます**（推測で表に整形すると、元の文章が黙って書き換わるため）
- Word のコードブロックの貼り付けには、Word 側で失われている情報のぶんだけ限界があります。**連続して並んだ 2 つのコードブロックは 1 つになります** — Word は同じスタイルの連続した段落をひと続きとして扱い、クリップボードにも境目が残らないためです。**言語（` ```js ` の `js`）は復元できません**（Word は書体しか持っていません。Mermaid / PlantUML の図も、貼り付け後は言語の無いコードブロックになります）。**Markdown → Word 出力の数式ブロックはコードブロックとして戻ります**（数式は Word へ出せないので、TeX のソースを等幅テキストとして書き出しているためです）。**表のセルの中のコードは本文のまま**です（Markdown の表のセルにコードブロックは置けません）
- プレビューの画像表示は相対パスと `data:` URI のみ。外部 `http(s)` 画像・絶対ローカルパスはプレースホルダ表示になります（Markdownソースはそのまま保持）
- ⚠ **画像の幅の変更はドラッグ操作だけです。** 四隅のハンドルはポインタの押下→移動→離しにしか反応せず、**キーボードにも、単一ポインタの操作（押して離すだけ）にも代替がありません**。WCAG 2.2 の **2.1.1「キーボード」（レベル A）**・**2.5.7「ドラッグ動作」**・**2.5.8「ターゲットのサイズ（最小）」**を満たしていません（ハンドルは 9×9 px で、2.5.8 の最小 24×24 px に足りません。ハンドルは画像そのものの上に載っているため、間隔による例外にも乗りません）。幅を数値で指定したいときは、**ツールバーの「ソースを開く」**でソースを横に並べて開き、`<img src="..." alt="..." width="480">` の `width` を直接書き換えてください（この形式はプレビューでもそのまま画像として表示され、リサイズが書き出すのと同じ形です）
- SVG は `<img>` として表示します（SVG 内のスクリプトは実行されません）。draw.io の SVG で文字が消える場合は、draw.io の書き出し設定で「テキストをパスに変換」を有効にしてください（`foreignObject` は `<img>` 表示で描画されないブラウザがあるため）
- **DOCX / XLSX 変換の SVG 画像はヘッドレス Chrome で PNG 化してから埋め込みます**（Word は PNG フォールバックの無い SVG を受け付けないため）。**draw.io の SVG はラベルが `foreignObject` に入っており、埋め込む SVG からはサニタイズで落ちてしまうので、その場合は PNG として埋め込みます**（Word での見た目は同じ）。Chrome が無い環境では従来どおり警告して alt テキストになります
- DOCX / XLSX 変換が読み込む画像は**ローカルファイルと `data:` URI だけ**です。外部 `http(s)` 画像は取得せず、警告して alt テキストになります（`IMG003`）。ローカルファイルはワークスペース外・UNC・シンボリックリンクも読みます（従来どおり。1 画像 10MB / `data:` は 2MB が上限）
- ⚠ **MD → PDF 変換は、文書内に外部 `http(s)` 画像があると、印刷を行うローカルのブラウザがそれを取得して PDF に描画します**（現状は警告も出ません）。プレビュー・DOCX / XLSX 変換は取得しません。外部取得の抑止は対応を予定しています。それまでは、外部にアクセスさせたくない文書では、画像をローカルファイルにしてから PDF 変換してください（貼り付けた画像はもともとローカルファイルとして保存されます）
- 表はGFM準拠（先頭行がヘッダー・セル内はインライン内容・セル結合なし）。編集した表は列幅パディングが正規化されます
- 検索の「単語単位」は英数字にだけ効きます（単語境界の定義上、日本語では一致しません）。保護中のブロックは中身がまとめて 1 件の一致として扱われ（ブロック全体が強調されます）、置換の対象にはなりません
- リンクの Ctrl+クリックで開くのは `http(s)` / `mailto:` / 文書フォルダ配下の相対パス / `#見出し` だけです。`javascript:` / `file:` / `vscode:` などのスキームと絶対パスは開きません
- GitHub Alerts はプレビュー・HTML・PDF・**Word** で色付きの囲みになります（Word では種類ごとの背景色・左罫線と、**その文書の言語**の見出し（日本語なら「ノート」「重要」等、英語なら `Note` / `Important` 等）が付き、`[!NOTE]` のマーカーは見出しに置き換わります。**Excel はメタシートに本文をそのまま書き出すので囲みにはなりません**）。GitHub 本家はマーカーが 1 行目に単独で置かれている場合だけを Alert と見なしますが、本製品は `> [!NOTE] 本文` のように 1 行で書いた場合も Alert として扱います（プレビュー上は 2 行形式と区別できないため。プレビューと変換結果が食い違わないことを優先しました）
- Mermaid / PlantUML はプレビュー・HTML・PDF・**DOCX** で描画されます。**Excel は `glyphcove.xlsx.mode` が `report` のときだけ**画像として入ります（既定の `data` は表だけの出力なので、図の描画も行いません）。描画できない環境（Chrome が無い、PlantUML の Java / jar が無い、図の構文エラー）では**コードブロックのまま出力し、理由を警告に出します**（`DIA002` / `DIA003`）。**文書内の図はまとめて 1 回で描画**するので、図の数だけブラウザが起動することはありません
- DOCX に入る図の**表示サイズは図そのもののサイズ**です（ページ幅を超えるものだけ縮小）。設定 `svg` と `png` で表示サイズは変わりません（違うのは拡大したときの綺麗さとファイルサイズだけです）
- DOCX 変換の**目次はフィールド**です。Word で開いた直後は「目次のエントリが見つかりません」と出ることがあり、目次を選んで **F9** を押すと展開されます（Word の仕様）。**ページ番号は印刷レイアウト表示でのみ正しく出ます**（下書き / Web レイアウトでは Word が改ページを計算しないため。目次フィールドには Word 自身と同じ `\z` を付けてあり、その場合はページ番号を出しません）
- DOCX 変換では、画像だけの段落は**中央寄せ**になります（図として扱うため。文章の中に混ざった画像は行の流れのままです）
- **数式は `$$…$$` だけを数式として扱います**（ブロックも、段落中のインラインも同じ記法）。
  **GitHub 互換の `$…$` は数式にしません** — 同じ行に `$` が 2 つあるだけで
  `$100〜$200` のような通貨表記や `$HOME` が数式に化け、さらに編集時に `\$100` へ
  書き換わってしまうためです（実測。[アーキテクチャと ADR](../architecture.ja.md) の「インライン数式」の ADR）。
  なお ` ```math ` のコードブロックも数式にはなりません（コードブロックのままです）。
  インライン数式の中の改行は半角スペースに畳まれます（TeX では改行は空白と同じ意味です）。
  **DOCX 変換では数式は描画されず、TeX のソースが等幅テキストとして出力されます**（警告付き）。
  埋め込み用（standalone でない）HTML 出力には KaTeX の CSS が入らないため、体裁が崩れます（警告付き）
- PlantUML はセキュリティのため SANDBOX プロファイルで実行します。**`!include` によるローカルファイル・URL の取り込みは使えません**（jar 内蔵の標準ライブラリ `!include <C4/…>` 等は使えます）。1 つのコードブロックに書ける図は 1 つです（`@startuml` を 2 つ以上書くとエラー表示）
- PDFのヘッダー/フッター、スキャンPDFのOCRは未対応（すべて警告で明示）。PDF→MD の画像は**ラスタ画像のみ**で、**図形として描かれた図は取り出せません**（PDF には画像が存在しないためで、検出もできません — 表の罫線も同じ描画命令で表現されており、区別する手段がありません）
- front matter の編集は**生の YAML のみ**です（キー/値のフォーム UI はありません。フォームでは YAML のコメントとキー順序が往復で壊れるため）。**本文に単独の `---` 行があるなど、front matter として読み戻せない内容は保存を拒否します**（そのまま書くと front matter がそこで終わり、残りが見出しなどに化けるため）。編集中に文書が外部から書き換えられた場合、開いていた編集内容は破棄されます
- 方言はGFM＋YAML Front Matter固定。改行コード（LF/CRLF）は維持
