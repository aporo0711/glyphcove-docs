# FAQ（よくある質問）

**English**: [faq.md](faq.md)

## 本当に何も外部へ送信しませんか?

**文書そのものが外部へ送られることはありません。** クラウド API を呼ばず、テレメトリ（利用状況の収集）もありません。プレビューと Word / Excel 変換は外部の `http(s)` 画像も読み込みません。PDF 印刷が使うのも、端末にインストール済みの Edge / Chrome の実行ファイルです。

既知の例外が 1 つあります: **PDF 変換**は、文書に外部 `http(s)` 画像が含まれていると、印刷を行うローカルのブラウザがそれを取得します（詳細と回避策は[既知の正規化・制限](limitations.ja.md)。抑止は対応を予定しています）。

これは信じていただく話ではなく、確認できる話です。リソースモニターや TCPView、プロキシのログで、ご自身の環境の通信をそのまま確かめられます。裏返すと、**作者にも、あなたが何を変換したかは分かりません** — 収集していないので、知る手段がそもそもありません。詳細は[セキュリティ](security.ja.md)にあります。

## Edge が入っているのに PDF が出ません

一部の環境の Edge は、ヘッドレス印刷に応答しません（正常終了するのに何も出力しない）。本製品はインストール済みのブラウザを順に試し、**実際に PDF を生成できたもの**を使います。Edge が応答しない場合は自動で Chrome に切り替え、その旨を警告に出します。どのブラウザでも生成できないときは、設定 `glyphcove.pdf.browserPath` で実行ファイルを直接指定してください。詳細は[必要ランタイム・外部ツール](requirements.ja.md)にあります。

## PlantUML の図が描画されません

PlantUML の描画には Java 8 以上と plantuml.jar が必要です。**jar は本製品に同梱していません** — どのライセンスの版を使うかは利用者が選べるべきものだからです。PlantUML 拡張機能（`jebbs.plantuml`）が入っていれば、その同梱 jar を自動で再利用するので入手は不要です。MIT 版を選ぶ手順や jar の版によるトラブルは[必要ランタイム・外部ツール](requirements.ja.md)にまとめています。描画できない場合、図はコードブロックのまま出力され、理由が警告に出ます。

## プレビューでは Mermaid の図が見えるのに、変換するとコードブロックになります

変換（HTML / PDF / Word / Excel）では図を SVG や PNG に事前描画する必要があり、そこに Edge / Chrome を使います（自動検出）。見つからない環境では図をコードブロックのまま出力し、理由を警告（`DIA002`）に出します。詳細は[必要ランタイム・外部ツール](requirements.ja.md)にあります。

## Excel からコピーした表を貼ったら、結合セルの列がずれました

既知の制限です。Excel の表は現状の動作を変えないため無変換で貼り付けており、結合セルは解除されず列がずれます（Word・Web ページの表は貼り付け時に結合を解除し、値を左上のセルへ入れて通知します）。回避策は、**Excel 側でセル結合を解除してからコピーする**ことです。ほかの制限は[既知の正規化・制限](limitations.ja.md)にあります。

## 変換した Word で目次が「目次のエントリが見つかりません」になります

不具合ではなく Word の仕様です。本製品が出力する目次は**本物の目次フィールド**なので、Word で開いた直後は未計算のことがあります。目次を選択して **F9** を押すと展開されます。ページ番号は印刷レイアウト表示でのみ計算されます（下書き / Web レイアウトでは Word が改ページを計算しないため）。

なお、目次と図表番号は設定で有効にして変換します（`glyphcove.docx.toc` / `glyphcove.docx.numberCaptions`。**どちらも既定はオフ**です）。

## 変換で何が失われますか?

Markdown が Word のすべてを表現できないのは当然で、逆もまた同じです。どの方向にロスがあるかは README の「変換できる組み合わせ」の表に、個々の内容は[変換](conversion.ja.md)と[既知の正規化・制限](limitations.ja.md)に書いてあります。大事なのは、**落ちたものは原則として警告と品質レポートで報告する**ことです（原理的に検出できないもの — PDF の中で図形として描かれた図など — は[既知の正規化・制限](limitations.ja.md)に列挙しています）。列が 1 つ黙って消えたファイルは、変換の代償ではなく不具合として扱います。

## いま無料で使える機能が、あとから有料になりますか?

将来のリリースで有償の Pro ライセンスの対象にする予定の機能はあります（Word / Excel への出力・逆変換など）。ただし、その線は README の「[料金の予定（事前のお知らせ）](../README.ja.md)」にあらかじめ全部書いてあり、**「無料のまま」と宣言した機能（編集・プレビュー・貼り付け・HTML / PDF の基本出力）をあとから有償に移すことはしません**。時期は約束しません。バージョンが明示するまでは、すべての機能が無料のままです。

## 会社で・商用で使ってよいですか?

はい。**無償で、商用・非商用を問わず、期間の制限なく使えます**（台数や人数の制限もありません）。クローズドソースの製品で、再配布はできません。要点は README の[ライセンス節](../README.ja.md)に、効力を持つ全文は同梱の LICENSE にあります。

## Pro の価格はいくらになりますか?

未定です。決まりしだい、実施より先に README と CHANGELOG でお知らせします（時期はお約束しません）。どの機能が対象になる予定かは、すでに README の「料金の予定（事前のお知らせ）」に書いてあります。

## 不具合を見つけました。どこに報告すれば、いつ返事が来ますか?

窓口は GitHub の [Issues](https://github.com/aporo0711/glyphcove-docs/issues) の 1 本です。書きかたは [CONTRIBUTING.md](../../CONTRIBUTING.md) にあります（最小の再現サンプルがあると助かります。機密にあたる内容は取り除いてください）。

1 人で開発しています。お問い合わせへの返信は平日の夜と週末になり、数日かかることがあります。文書や出力ファイルが壊れる不具合を最優先で確認します。ご要望はすべて読みますが、実装をお約束することはできません。

脆弱性と思われるものは公開の Issue にせず、[SECURITY.md](../../SECURITY.md) の非公開報告をお使いください。
